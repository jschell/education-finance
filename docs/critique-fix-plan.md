# Critique fixes · v0.10.0

Status: implementation in progress. Protocol frozen before new scores are computed, 2026-11-16.

1. **Whole-plan validation.** Use the production compiler, investment/cost path factory and bill-paying ledger for synthetic one-student plans at annual forecast origins. Train all macro, cost and error inputs through that origin only. Test 0/4/8-year waits followed by four attendance years, three funding levels and all five cost sectors. Record predicted funding frequency, actual payment success, Brier score versus 50%, cost interval coverage, origin counts and overlapping outcome windows. Historical anchors come from training data, not today's survey. These are reconstructed historical plans, not observed family outcomes or historical survey-vintage forecasts. Explicitly count unavailable 18-year-wait tests. Never use these results to tune this release.
2. **Cost uncertainty.** Candidate persistent paired price uncertainty comes from earlier rolling forecast errors, with each target year counted once using its maximum absolute annualized tuition/housing error across sectors/horizons. An origin uses only target years through that origin. With at least five target years, use the finite-sample 80% order statistic and a symmetric uniform annual log drift whose central 80% extent matches it. This is conservative sensitivity widening, not an independence-based coverage guarantee. Compare the candidate with the unchanged v0.9 correction on the same rolling folds and seeds. Enable only if equal-era/horizon/sector normalized interval score is at most 10% worse overall AND absolute distance from 80% coverage improves overall. Publish period scores including failures. Otherwise retain baseline and report the unclosed critique; do not tune the candidate after evaluation.
3. **Savings stability.** Fit the requested funding quantile plus a declared sampling reserve of three binomial standard errors for a 5,000-path independent verification. Cap fitting probability at 1. Verify the rounded contribution on 5,000 separate paths and report its one-sided 95% Wilson lower bound; require that lower bound to meet the requested target. Do not refit to the verification sample or change the user's target. Report failed verification clearly. This reserve addresses Monte Carlo noise only. Test several seeds and date/ceiling edge cases.
4. **Meaning of ranges.** Keep one Calculate action. Label the headline as an assumption-case range, explicitly with no probability weight or confidence level. Describe missing old joint cost history, short long-horizon evidence and extrapolation without claiming these are repaired by more Monte Carlo trials.
5. **Maintenance.** Separate random/quantile utilities from the unused lognormal simulation engine. Remove that unused production engine and replace its obsolete tests with tests of the live simulation. Rewrite README around current behavior and move release history into an archive. Make current model documentation authoritative, retain past protocols/reports for reproduction, align versioned imports and preserve schema-5 student funding.
6. **Completion.** Generate reproducible reports, verify origin cutoffs, shared household paths, contribution reserve behavior, responsive/keyboard/project-prefix UI and all repository checks. Deploy through existing GitHub Actions. Then review the final implementation afresh, recording resolved, partial and unresolved findings with severity and concrete evidence. No claim that passing code tests calibrates economic probabilities.
